# Digital Circuit Workflow Design

> **Design reliable AI automations in n8n from behavior first, then map that behavior to digital-circuit patterns.**

مهارة منهجية لتصميم أتمتة الذكاء الاصطناعي في **n8n** أو الأدوات المشابهة، عبر تحليل السلوك المطلوب أولًا ثم اشتقاق بنية سير العمل من الدوائر الرقمية وهندسة الأنظمة.

## لماذا هذه المهارة؟

تتوسع أتمتة الذكاء الاصطناعي بسرعة، لكن وصل العقد عشوائيًا قد يؤدي إلى قرارات متذبذبة، وإعادة محاولات غير محدودة، وصعوبة في التعامل مع التعارض أو الفشل الجزئي. تساعد هذه المهارة على تحويل المتطلب السلوكي إلى تصميم يمكن شرحه واختباره: نحلل المدخلات والمخرجات والحالة وحدود الفشل، نختار نمطًا رقميًا مناسبًا، نترجمه إلى عقد n8n، ثم نكتب JavaScript مع معالجة لحالات الحافة.

## ابدأ خلال 10 دقائق

1. افتح [SKILL.md](SKILL.md) لقراءة المنهج الكامل.
2. اختر المثال الأقرب إلى المشكلة التي تريد حلها:
   - [majority-gate.js](examples/majority-gate.js): قبول قرار عند اتفاق عدد كافٍ من المقيّمين.
   - [priority-encoder.js](examples/priority-encoder.js): اختيار المسار الأعلى أولوية بصورة حتمية.
   - [hysteresis-router.js](examples/hysteresis-router.js): منع تقلب القرار قرب عتبة الثقة.
   - [state-machine.js](examples/state-machine.js): إدارة الحالات ووضع حد لإعادة المحاولة.
3. في n8n، أضف عقدة **Code** وأدخل البيانات في `items` بالشكل الذي يتوقعه المثال.
4. شغّل المثال أولًا ببيانات عادية، ثم جرّب حالة ناقصة أو متعارضة أو قريبة من العتبة.
5. إذا وجدت شيئًا غير واضح، افتح [ملاحظة اختبار جديدة](../../issues/new?template=tester-feedback.md) واذكر اسم المثال والنتيجة الفعلية.

### مثال سريع: Hysteresis Router

إدخال متوقع:

```json
{
  "confidence": 0.84,
  "previous_state": "REVIEW"
}
```

هذا المثال لا يرسل بيانات إلى خادم خارجي. وهو يوضح الفرق بين عتبة الدخول إلى `AUTO_SEND` وعتبة الاستمرار فيه؛ لذلك لا يتغير القرار بسبب اهتزاز بسيط حول عتبة واحدة.

## خريطة الأنماط

| السلوك المطلوب | النمط الرقمي | استخدامه في الأتمتة |
|---|---|---|
| توافق عدة نماذج أو مقيمين | Majority Gate | قبول القرار عند تحقق نصاب توافق محدد |
| حل تعارض حسب الخطورة | Priority Encoder / Arbiter | تصعيد الطلبات الحساسة قبل الطلبات العادية |
| تثبيت القرار قرب العتبة | Latch / Hysteresis | منع التقلب بين المراجعة والإرسال التلقائي |
| تذكّر النتائج | Counter / Accumulator | حفظ المحاولات والتغطية والأدلة |
| إدارة دورة حياة | Finite State Machine | منع الانتقالات غير المسموحة |
| إعادة الأجزاء الفاشلة فقط | Feedback Loop | تحسين الجزء الفاشل مع حد واضح للمحاولات |
| اعتماد آمن | Safety Interlock + OR Gate | النشر فقط عند نجاح فحص الأمان وشرط قبول مناسب |
| تدقيق الإنصاف | Comparator Bank + Safety Interlock + Latch/Hysteresis | فحص الفروق والاختبارات المقابلة ومنع القرار عند نقص الدليل |

## المنهج

تبدأ كل عملية تصميم بتفكيك النظام إلى شرائح وظيفية مستقلة، مع توثيق المسؤولية والمدخلات والمخرجات والمالك الحقيقي للحالة وحدود الفشل. بعد ذلك نحلل السلوك قبل اختيار النمط، ونشرح المبدأ الرقمي في صورته المجردة، ثم نربط عناصره بعقد n8n أو بمخزن حالة أو بطابور عند الحاجة. وأخيرًا نكتب كودًا قابلًا للتنفيذ مع التحقق من البيانات، والتزامن، والتكرار، وإعادة المحاولة، والمهل الزمنية، والتسليم المكرر أو الخارج عن الترتيب.

## أحتاج إلى مختبرين

لا يلزم أن تكون خبيرًا في الدوائر الرقمية. جرّب مثالًا واحدًا أو اقرأ خطوة واحدة من `SKILL.md`، ثم أخبرني:

- ما الذي فهمته فورًا؟
- ما الجزء الذي احتاج إلى شرح أو مثال إضافي؟
- هل استطعت تحويل المثال إلى عقدة **Code** في n8n؟
- ما حالة الحافة التي ينبغي إضافتها إلى الاختبارات؟

يمكن إرسال الملاحظات عبر [Issue جديد](../../issues/new?template=tester-feedback.md). من فضلك لا تضع مفاتيح API أو بيانات شخصية أو أسرارًا في الملاحظة.

## ملاحظة أمنية

لا ينبغي اعتبار تشبيه الدائرة ضمانًا أمنيًا. يجب فصل الأسرار عن ملفات JSON، واستخدام مخزن حالة مناسب، والتحقق من صلاحيات الخدمات الخارجية، وإضافة مسار فشل آمن ومراجعة بشرية للقرارات عالية المخاطر. الأمثلة تعليمية، ويجب اختبارها في بيئة آمنة قبل استخدامها في الإنتاج.
